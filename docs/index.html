Ray 读写 S3 上的 Lance 数据集

用 Ray Data 在 S3（及 MinIO 等 S3 兼容存储）上分布式读写 Lance 列存数据集：三种写法、S3 配置、版本兼容性，以及实测踩到的坑。

实测环境：Ray 2.59.0 · pylance 13.0.0 / 4.0.2 · lance-ray 0.5.0 · pyarrow 25 · moto S3 · 2026-10

三种读写方式

方式一

Ray 内置

ray.data.read_lance / Dataset.write_lance。只需 ray[data] + pylance，写入对 pylance 版本有要求。

方式二 · 推荐

lance-ray

lance_ray.read_lance / write_lance。Lance 官方维护，支持流式写入、按 fragment 读取和分布式运维。

方式三

两阶段写入

LanceFragmentWriter + LanceFragmentCommitter。写入前在 worker 上做 transform，driver 原子提交。

三种方式都只通过 storage_options 字典访问 S3。这个字典会被序列化发到每个 Ray worker，所以凭证要显式传进去，不能只靠 driver 进程的环境变量。

版本兼容性

环境组合读取Ray 内置写入lance-ray 写入
Ray 2.59 + pylance 13 + lance-ray 0.5✓✗ TypeError✓
Ray 2.59 + pylance 4.0.2 / 3.0.2，不装 lance-ray✓✓—（lance-ray 需要 pylance ≥ 9）
同一环境只能二选一 Ray 2.59 内置的 Lance datasink 会给 lance.fragment.write_fragments 传 storage_options_provider；pylance 从 6.0 起删掉了这个参数（换成 namespace_client），写入时报 TypeError: write_fragments() got an unexpected keyword argument 'storage_options_provider'。 lance-ray 0.5 又要求 pylance>=9。推荐装最新 pylance + lance-ray，写入一律用 lance-ray；ray.data.read_lance 在两种环境下都能用。

运行时检测当前环境能否用 Ray 内置写入：

from ray_lance_s3.io import ray_native_write_supported
ray_native_write_supported()   # pylance 13 → False；pylance 4.0.2 → True

S3 配置（storage_options）

Lance 用 Rust 的 object_store 访问对象存储。下面这些键名在 Ray、lance-ray 和 lance.dataset() 里都一样，值都是字符串。

键说明示例
aws_access_key_idAccess KeyAKIA...
aws_secret_access_keySecret Key
aws_session_token临时凭证（STS）
aws_region区域us-east-1
aws_endpointS3 兼容服务地址（MinIO / TOS / OSS 等）http://minio:9000
allow_httpendpoint 是 http:// 时必须设为 "true""true"
aws_virtual_hosted_style_request是否用 virtual-hosted 风格（部分云厂商要求开启）"true"

字段留空时会回退到 AWS 默认凭证链（环境变量 → ~/.aws → IAM Role / IRSA）。在 EKS 或 EC2 上用实例角色时，通常只需要 aws_region。

仓库里的 S3Config 负责生成这个字典：

from ray_lance_s3 import S3Config, s3_uri

# 1) 显式配置（MinIO）
opts = S3Config(
    access_key_id="minioadmin", secret_access_key="minioadmin",
    region="us-east-1", endpoint="http://minio:9000", allow_http=True,
).storage_options()

# 2) 从环境变量读取：AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY / AWS_REGION /
#    AWS_ENDPOINT_URL / AWS_ALLOW_HTTP / AWS_VIRTUAL_HOSTED_STYLE_REQUEST
#    endpoint 以 http:// 开头时自动设置 allow_http
opts = S3Config.from_env().storage_options()

uri = s3_uri("my-bucket", "warehouse", "events.lance")   # s3://my-bucket/warehouse/events.lance

方式一：Ray 内置 API

写入

import ray
from ray.data import SaveMode   # Ray ≥ 2.46；更早的版本直接传字符串 "create" / "append" / "overwrite"

ds = ray.data.read_parquet("s3://raw-bucket/events/")
ds.write_lance(
    "s3://my-bucket/warehouse/events.lance",
    mode=SaveMode.OVERWRITE,          # CREATE（默认，已存在则报错）/ APPEND / OVERWRITE
    min_rows_per_file=1024 * 1024,
    max_rows_per_file=64 * 1024 * 1024,
    storage_options=opts,
)

读取

ds = ray.data.read_lance(
    "s3://my-bucket/warehouse/events.lance",
    columns=["id", "label", "score"],           # 列裁剪：只从 S3 拉这几列
    filter="label = 'cat' AND score > 0.5",    # SQL 谓词，下推到 Lance 扫描器
    version=3,                                  # 可选：读历史版本（版本号或 tag）
    storage_options=opts,
    scanner_options={"batch_size": 8192},
)
n = ds.materialize().count()   # 带 filter 时不要直接 ds.count()，见“常见坑”

封装好的版本是 ray_lance_s3.ray_read_lance / ray_write_lance，后者会先检查版本兼容性，不兼容时直接报出可读的错误。

方式二：lance-ray（推荐）

import lance_ray as lr

# 批量写入
lr.write_lance(
    ds, "s3://my-bucket/warehouse/events.lance",
    mode="overwrite",                 # create / append / overwrite
    min_rows_per_file=100_000,        # 必须 ≤ max_rows_per_file
    max_rows_per_file=1_000_000,
    storage_options=opts,
)

# 流式写入：每个 batch 提交一个版本；中断后用 resume_rows 跳过已写入的行
lr.write_lance(ds, uri, mode="append", stream=True, batch_size=10_000, storage_options=opts)

# 读取
ds = lr.read_lance(
    uri,
    columns=["id", "score"],
    filter="score > 0.9",
    fragment_ids=[0, 1],                 # 只读指定 fragment
    dataset_options={"version": 1},      # 历史版本
    with_metadata=True,                  # 附带 _rowaddr / _fragid 元数据列
    storage_options=opts,
)

lance-ray 还支持 namespace（namespace_impl / namespace_properties / table_id），可以通过 REST / 目录 catalog 下发临时凭证，此时不用再传 uri 和静态凭证。

方式三：两阶段分布式写入

如果要在写入前对每个 batch 做 transform（例如计算 embedding），可以把写数据文件和提交版本拆开：

from lance_ray import LanceFragmentWriter, LanceFragmentCommitter
import pyarrow as pa, pyarrow.compute as pc

def enrich(tbl: pa.Table) -> pa.Table:          # 在 worker 上执行
    return tbl.append_column("score_pct", pc.multiply(tbl["score"], 100))

(
    ds.map_batches(
        LanceFragmentWriter(uri, transform=enrich, max_rows_per_file=1_000_000, storage_options=opts),
        batch_size=64 * 1024,
        batch_format="pyarrow",
    )
    .write_datasink(LanceFragmentCommitter(uri, mode="overwrite", storage_options=opts))
)

阶段一中有 worker 失败时不会提交任何版本，只会在 S3 上留下没被引用的数据文件；确认没有进行中的写入后，可以用 cleanup_old_versions(delete_unverified=True) 清掉。封装好的版本是 ray_lance_s3.write_fragments_then_commit。

数据集运维

lance-ray 把常见运维操作分发到 Ray 集群上执行，封装在 ray_lance_s3/maintenance.py：

import lance_ray as lr
import pyarrow as pa, pyarrow.compute as pc
from lance.optimize import CompactionOptions

# 分布式加列：只写新列的数据文件，不重写已有列
def is_high(batch: pa.RecordBatch) -> pa.RecordBatch:
    return pa.RecordBatch.from_arrays([pc.greater(batch["score"], 0.8)], names=["is_high"])
lr.add_columns(uri, transform=is_high, read_columns=["score"], storage_options=opts)

# 合并小文件（频繁 append 之后建议执行）
lr.compact_files(uri, compaction_options=CompactionOptions(target_rows_per_fragment=1_000_000),
                 num_workers=4, storage_options=opts)

# 分布式建标量索引：BTREE / BITMAP / INVERTED(FTS) / ...
lr.create_scalar_index(uri, column="id", index_type="BTREE", num_workers=4, storage_options=opts)

# 版本历史 / 清理旧版本
import lance
d = lance.dataset(uri, storage_options=opts)
d.versions()
d.cleanup_old_versions(older_than=timedelta(days=7))   # from datetime import timedelta

实测：连续 5 次 append 产生 5 个 fragment，compact_files 之后合并成 1 个（fragments_removed=5, fragments_added=1）。

常见坑

  1. Ray 内置写入与 pylance ≥ 6 不兼容：见版本兼容性，写入改用 lance-ray。
  2. 带 filter 的 read_lance(...).count() 返回未过滤的行数：Ray 2.59 实测，count() 直接用了元数据里的行数（100 行数据过滤后应为 50，返回 100）。需要准确行数时用 ds.materialize().count() 或实际迭代数据。
  3. lance-ray 的 min_rows_per_file 默认是 1,048,576：只调小 max_rows_per_file 会报 ValueError: min_rows_per_file ... must be less than max_rows_per_file，两个参数要一起改。
  4. 凭证必须放进 storage_options：只在 driver 上 export AWS_*，远端节点上的 worker 看不到。要么显式传参，要么用 IAM Role / IRSA。
  5. MinIO 等 http endpoint：需要同时设置 aws_endpoint 和 allow_http="true"；aws_region 也要填（MinIO 填 us-east-1 就行）。
  6. Ray 的 tensor 列写入后类型是 large_list<float>：而 Lance 的向量索引要求 fixed_size_list<float32, dim>。要建向量索引的话，写入时传 schema=，把向量列指定成 pa.list_(pa.float32(), dim)（已验证 lance_ray.write_lance 会按该 schema 写成 fixed_size_list<float>[dim]）。
  7. overwrite 不会删除旧数据：每次写入都会生成新版本，旧版本仍可 time travel，S3 用量会一直增长。定期执行 cleanup_old_versions()。
  8. 并发写同一个数据集：多个作业同时 append 时，Lance 会用乐观并发自动重试提交；overwrite 与其他写入并发会冲突，应当串行执行。

仓库结构与测试

ray_lance_s3/
  s3_config.py      # S3Config → storage_options
  io.py             # 三种读写方式 + ray_native_write_supported()
  maintenance.py    # add_columns / compact_files / create_scalar_index / list_versions
examples/
  01_ray_native.py        # Ray 内置读写 + 谓词下推 + time travel
  02_lance_ray.py         # lance-ray 批量/流式写入，按 fragment 读取
  03_fragment_writer.py   # 两阶段写入 + worker 端 transform
  04_maintenance.py       # 加列、合并小文件、建索引、版本列表
tests/                    # moto 本地 S3 端到端测试
docker-compose.yml        # 本地 MinIO

pip install -r requirements.txt
docker compose up -d
export AWS_ACCESS_KEY_ID=minioadmin AWS_SECRET_ACCESS_KEY=minioadmin AWS_REGION=us-east-1
export AWS_ENDPOINT_URL=http://localhost:9000 LANCE_S3_BUCKET=lance-demo
cd examples && python 02_lance_ray.py
